# Spring Boot — Chapter 12.10: Graceful Shutdown ⭐⭐⭐⭐⭐

One of the biggest differences between a **beginner application** and an **enterprise application** is **how it shuts down**.

Imagine this situation:

```text
User clicks "Pay Now"

↓

Payment Processing

↓

Server Suddenly Stops

↓

Money Deducted

↓

Response Never Returned
```

This is called an **abrupt shutdown**.

Enterprise systems avoid this using **Graceful Shutdown**.

# 1. What is Graceful Shutdown?

Graceful Shutdown means:

> **Stop accepting new requests, allow current requests to finish, clean up resources, and then stop the application.**

Instead of:

```text
Kill Process

↓

Everything Stops
```

Spring does:

```text
Stop New Requests

↓

Finish Current Requests

↓

Destroy Beans

↓

Close Resources

↓

Exit
```

---

# 2. Why Do We Need It?

Imagine an employee is uploading a 2 GB file.

Without graceful shutdown:

```text
Upload Started

↓

Server Stops

↓

Upload Failed

↓

User Must Restart
```

With graceful shutdown:

```text
Upload Started

↓

Shutdown Requested

↓

Upload Completes

↓

Server Stops
```

Much better user experience.

---

# 3. Abrupt Shutdown vs Graceful Shutdown

### Abrupt Shutdown

```text
Request 1

↓

Processing

↓

Server Killed

↓

Request Lost
```

Problems:

* Incomplete database transactions
* Lost API responses
* Broken uploads
* Partial file writes

---

### Graceful Shutdown

```text
Shutdown Requested

↓

Stop Accepting New Requests

↓

Wait for Running Requests

↓

Complete Processing

↓

Shutdown
```

---

# 4. Spring Boot Configuration

Enable graceful shutdown:

```properties
server.shutdown=graceful
```

By itself, this only enables graceful shutdown.

You should also configure how long Spring waits:

```properties
spring.lifecycle.timeout-per-shutdown-phase=30s
```

Meaning:

```text
Shutdown Requested

↓

Wait up to 30 seconds

↓

If Requests Finish

↓

Shutdown

Else

↓

Force Shutdown
```

# 6. What Happens Internally?

Suppose Spring Boot uses the embedded Tomcat server.

Internally:

```text
Tomcat Running

↓

Pause Connector

↓

Reject New Connections

↓

Allow Worker Threads to Finish

↓

Close Context

↓

Destroy Beans

↓

Stop JVM
```

Notice:

**Existing worker threads continue.**

Only new requests are rejected.

# 7. Example

Suppose this API takes 20 seconds.

```java
@RestController
public class ReportController {

    @GetMapping("/report")
    public String report() throws Exception {

        Thread.sleep(20000);

        return "Completed";
    }
}
```

Scenario:

```text
User Calls /report

↓

Processing...

↓

Shutdown Requested

↓

Spring Waits

↓

Report Completes

↓

Response Returned

↓

Application Stops
```

Without graceful shutdown:

```text
User Calls API

↓

Server Stops

↓

Connection Lost
```

# 8. Docker Flow

Suppose:

```bash
docker stop employee-api
```

Docker sends:

```text
SIGTERM
```

Flow:

```text
docker stop

↓

SIGTERM

↓

Spring Graceful Shutdown

↓

Finish Requests

↓

Container Stops
```

If the timeout expires, Docker sends `SIGKILL`, which immediately terminates the process.

# 11. Interaction with `@PreDestroy`

Remember:

```text
Shutdown

↓

Finish Requests

↓

Close Context

↓

@PreDestroy

↓

Application Stops
```

So `@PreDestroy` runs **after active requests are completed** but before beans are destroyed.

Example:

```java
@Service
public class CacheService {

    @PreDestroy
    public void cleanup() {

        cache.flush();
    }
}
```

This ensures cleanup occurs during shutdown.

# 13. Common Mistakes

### Mistake 1

Not enabling graceful shutdown.

```properties
# Missing
server.shutdown=graceful
```

The application may stop immediately depending on the environment.

---

### Mistake 2

Very small timeout.

```properties
spring.lifecycle.timeout-per-shutdown-phase=2s
```

Long-running requests may still be interrupted.

---

### Mistake 3

Very large timeout.

```properties
spring.lifecycle.timeout-per-shutdown-phase=30m
```

Deployments become unnecessarily slow.

Choose a value based on your application's workload.

---

# 14. Best Practices

```text
✅ Enable graceful shutdown in production

✅ Configure a realistic timeout

✅ Keep request processing efficient

✅ Use @PreDestroy for cleanup

✅ Test shutdown during deployments

❌ Don't force kill the JVM if avoidable

❌ Don't ignore long-running requests

❌ Don't perform heavy new work during shutdown
```

# 15. Interview Questions

### What is graceful shutdown?

> Graceful shutdown is the process of stopping an application by first rejecting new requests, allowing active requests to finish, cleaning up resources, and then terminating.

---

### How do you enable graceful shutdown?

```properties
server.shutdown=graceful
```

---

### How do you configure the shutdown timeout?

```properties
spring.lifecycle.timeout-per-shutdown-phase=30s
```

---

### What signal does Docker send first?

> Docker sends **SIGTERM**, giving the application a chance to shut down gracefully before eventually sending **SIGKILL** if necessary.

---

### What happens to active requests?

> Active requests are allowed to complete within the configured timeout. New requests are rejected.

---

### Does `@PreDestroy` run during graceful shutdown?

> Yes. It runs during the bean destruction phase after the application context begins closing.

# 17. Quick Comparison

| Abrupt Shutdown       | Graceful Shutdown            |
| --------------------- | ---------------------------- |
| Stops immediately     | Waits for active requests    |
| May lose data         | Reduces risk of data loss    |
| Drops connections     | Rejects only new connections |
| Unsafe for production | Recommended for production   |
