```text

    ↓
Compile
    ↓

Wait 20–30 Seconds
```

Imagine repeating that **hundreds of times every day**.

Spring Boot **DevTools** solves this problem by automatically restarting your application whenever you change your code.

# 1. What is Spring Boot DevTools?

Spring Boot DevTools is a **development-only module** that improves developer productivity.

It provides features such as:

* Automatic application restart
* Live browser reload (with browser extension)
* Development-friendly default properties

**Important:**

> DevTools is **not for production**.

---

Without DevTools:

```text

This becomes repetitive.

With DevTools:

```

Development becomes much faster.

# 3. Adding DevTools

### Maven

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-devtools</artifactId>
    <scope>runtime</scope>
    <optional>true</optional>
</dependency>
```

Why `runtime`?

Because DevTools is only needed while running the application during development.

Why `optional`?

So projects depending on yours don't automatically inherit DevTools.

# 4. Automatic Restart

Suppose you change:

```java
@GetMapping("/hello")
public String hello() {

    return "Hello";
}
```

to

```java
@GetMapping("/hello")
public String hello() {

    return "Hello Spring Boot";
}
```

Save the file.

DevTools detects:

```text
Class File Changed

↓

Restart Application

↓

New Code Active
```

No manual restart needed.

---

# 5. How Does DevTools Detect Changes?

The IDE compiles your Java source into `.class` files.

Example:

```text
EmployeeController.java

↓

EmployeeController.class
```

DevTools watches:

```text
target/classes
```

or

```text
build/classes
```

When a `.class` file changes:

```text
Modified Class

↓

DevTools Detects Change

↓

Restart Triggered
```

---

# 6. What Gets Restarted?

This is important.

DevTools **does not restart the JVM**.

Instead:

```text
JVM
│
├── Keeps Running
│
└── Restarts Spring ApplicationContext
```

Meaning:

```text
Old ApplicationContext

↓

Destroyed

↓

New ApplicationContext

↓

Application Ready
```

This is much faster than restarting the entire JVM.

# 8. Live Reload

Restart updates the backend.

Live Reload updates the browser.

Without Live Reload:

```text
Backend Restart

↓

Developer Presses F5
```

With Live Reload:

```text
Backend Restart

↓

Browser Refreshes Automatically
```

To use this, you typically install a LiveReload browser extension or use compatible tooling.

---

# 9. Restart vs Reload

Many developers confuse these terms.

| Restart                  | Reload              |
| ------------------------ | ------------------- |
| Backend restarts         | Browser refreshes   |
| Spring context recreated | HTML page refreshed |
| Java classes updated     | UI updated          |

Flow:

```text
Save Java File

↓

Restart Backend

↓

Reload Browser
```

# 12. Two ClassLoader Mechanism

One of the reasons DevTools restarts quickly is its use of **two class loaders**.

```text
JVM

├── Base ClassLoader
│      │
│      ├── Spring Framework
│      ├── Third-party Libraries
│      └── Dependencies
│
└── Restart ClassLoader
       │
       ├── Your Controllers
       ├── Your Services
       ├── Your Repositories
       └── Your Configurations
```

When you change your code:

```text
Restart ClassLoader

↓

Destroyed

↓

Recreated
```

The base class loader remains untouched.

This makes restarts much faster because dependencies don't need to be reloaded.

# 14. Common Mistakes

### Mistake 1

Using DevTools in production.

Wrong:

```xml
spring-boot-devtools
```

inside a production deployment.

DevTools is intended **only for development**.

---

### Mistake 2

Expecting every change to restart the application.

Some changes (like static resources or certain IDE configurations) behave differently depending on your build setup.

---

### Mistake 3

Thinking DevTools replaces Docker or Kubernetes hot deployment.

It doesn't.

DevTools is purely a local development convenience.

---

# 15. Best Practices

```text
✅ Use DevTools only during development

✅ Keep it as a runtime development dependency

✅ Use automatic restart to speed up coding

✅ Combine with Live Reload for frontend work

❌ Don't package DevTools for production

❌ Don't rely on it in deployed environments

❌ Don't confuse restart with browser reload
```

# 16. Interview Questions

### What is Spring Boot DevTools?

> A development-time module that improves productivity by providing automatic restart, Live Reload support, and development-friendly defaults.

---

### Does DevTools restart the JVM?

No.

It restarts the **Spring ApplicationContext**, while the JVM continues running.

---

### What triggers a restart?

A change in compiled application classes (typically under `target/classes` or `build/classes`).

---

### What is Live Reload?

A feature that automatically refreshes the browser after backend changes (when supported by the browser/tooling).

---

### Why is DevTools faster than restarting the application manually?

Because it uses a **two-classloader mechanism**, reloading only application classes instead of all framework libraries.

---

### Should DevTools be used in production?

No.

It is intended only for development.
