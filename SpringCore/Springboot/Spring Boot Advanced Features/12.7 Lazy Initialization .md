# Spring Boot — Chapter 12.7: Lazy Initialization (`@Lazy`) ⭐⭐⭐⭐⭐

One of the biggest questions in Spring is:

> **When does Spring create a bean?**

The answer is:

**By default, Spring creates singleton beans eagerly during application startup.**

`@Lazy` changes this behavior.

Understanding eager vs lazy initialization is very important for interviews and enterprise applications.

# 1. What is Lazy Initialization?

Lazy Initialization means:

> **Don't create the bean during application startup. Create it only when it is needed for the first time.**

Think of it like this:

Without lazy loading:

```text
Restaurant Opens

↓

Chef prepares EVERY dish

↓

Customer arrives
```

Wasteful.

With lazy loading:

```text
Restaurant Opens

↓

Customer Orders Pizza

↓

Chef Makes Pizza

↓

Serve Customer
```

Only what is needed is created.

---

# 2. Default Spring Behavior (Eager Initialization)

Consider these beans:

```java
@Service
public class EmployeeService {
}
```

```java
@Service
public class DepartmentService {
}
```

```java
@Service
public class SalaryService {
}
```

Startup:

```text
Application Starts

↓

Create EmployeeService

↓

Create DepartmentService

↓

Create SalaryService

↓

Application Ready
```

Even if `SalaryService` is never used, it is still created.

This is called **eager initialization**.

---

# 3. Why Does Spring Use Eager Initialization?

Spring intentionally creates beans early because it helps detect problems at startup.

Example:

```java
@Service
public class EmployeeService {

    private final UnknownService service;

    public EmployeeService(UnknownService service) {
        this.service = service;
    }
}
```

Startup:

```text
Create EmployeeService

↓

UnknownService Missing

↓

Startup Fails Immediately
```

This is actually helpful because configuration errors are caught before users access the application.

---

# 4. Introducing `@Lazy`

```java
@Service
@Lazy
public class ReportService {

    public ReportService() {
        System.out.println("ReportService Created");
    }
}
```

Now the startup changes.

Without `@Lazy`:

```text
Application Starts

↓

ReportService Created
```

With `@Lazy`:

```text
Application Starts

↓

ReportService NOT Created
```

Nothing happens yet.

---

# 5. When is the Bean Created?

The bean is created when it is first requested.

```text
Application Starts

↓

No ReportService

↓

User Requests Report

↓

Create ReportService

↓

Return Bean
```

This is called **lazy loading**.

---

# 6. Example

```java
@Service
@Lazy
public class ReportService {

    public ReportService() {
        System.out.println("Constructor Called");
    }
}
```

Controller:

```java
@RestController
public class ReportController {

    private final ReportService reportService;

    public ReportController(ReportService reportService) {
        this.reportService = reportService;
    }

    @GetMapping("/report")
    public String report() {
        return "OK";
    }
}
```

If `ReportService` is injected into a controller, Spring injects a **lazy proxy**. The actual `ReportService` object is created only when a method on it is first invoked.

Flow:

```text
Application Starts

↓

Controller Created

↓

Lazy Proxy Injected

↓

User Calls /report

↓

Proxy Creates ReportService

↓

Business Method Executes
```

---

# 7. Lazy Dependency

Example:

```java
@Service
public class EmployeeService {

    private final ReportService reportService;

    public EmployeeService(
            @Lazy ReportService reportService) {

        this.reportService = reportService;
    }
}
```

Here:

```text
EmployeeService

↓

Created Immediately

↓

ReportService

↓

Created Later
```

Only the dependency is lazy.

# 8. Internal Working

Without lazy:

```text
Spring Startup

↓

Create Bean

↓

Store in Context
```

With lazy:

```text
Spring Startup

↓

Create Proxy

↓

Store Proxy

↓

Method Call

↓

Create Real Bean

↓

Delegate Call
```

Spring often uses proxies to implement lazy initialization.

---

# 9. Global Lazy Initialization

Instead of annotating each bean:

```java
@Lazy
```

Enable globally:

```properties
spring.main.lazy-initialization=true
```

Now almost every eligible singleton bean becomes lazy.

Startup:

```text
Application Starts

↓

Minimal Beans Created

↓

Others Created On Demand
```

Without lazy:

```text
↓

30 Seconds
```

With lazy:

```text

```

# 13. Common Mistakes

### Mistake 1

Making every bean lazy.

```properties
spring.main.lazy-initialization=true
```

Not always a good idea.

Why?

Errors are discovered later.

Example:

```text
Application Starts Successfully

↓

First User Logs In

↓

Bean Creation Fails

↓

Production Error
```

Instead of failing at startup.

---

### Mistake 2

Using lazy for frequently used beans.

Example:

```text
AuthenticationService

↓

Every Request Uses It
```

Making it lazy gives little or no benefit.

---

### Mistake 3

Ignoring the first-request delay.

```text
User

↓

First API Call

↓

Create Bean

↓

Execute Logic
```

The first request may be slower.

---

# 14. `@Lazy` vs Eager Initialization

| Eager                   | Lazy                      |
| ----------------------- | ------------------------- |
| Created at startup      | Created when first needed |
| Faster first request    | Slower first request      |
| Startup may be slower   | Startup is faster         |
| Errors found early      | Errors may appear later   |
| Default Spring behavior | Optional behavior         |

---

# 15. Best Practices

```text
✅ Use lazy for expensive, rarely used beans

✅ Use lazy for optional modules

✅ Use lazy for heavy reporting engines

✅ Profile startup before optimizing

❌ Don't make everything lazy

❌ Don't use lazy to hide configuration problems

❌ Don't use lazy for critical beans used on every request
```

# 16. Interview Questions

### What is Lazy Initialization?

> Lazy initialization delays bean creation until it is first requested instead of creating it during application startup.

---

### What is the default behavior in Spring?

> Singleton beans are eagerly initialized during application startup.

---

### What does `@Lazy` do?

> It instructs Spring to defer the creation of a bean until it is actually needed.

---

### Can lazy initialization improve startup time?

> Yes. Fewer beans are created during startup, which can reduce startup time and initial memory usage.

---

### What are the disadvantages?

* First use may be slower.
* Configuration or dependency errors may appear later instead of during startup.

---

### Can lazy initialization be enabled globally?

Yes.

```properties
spring.main.lazy-initialization=true
```
